Tracking lab · incidents #03, #04, #05, #10

Capture the click once, keep it 90 days, and count the lead once

A working demo of the snippet the brands' sites would run. It fixes four incidents of the audit: UTMs lost after a redirect (#03), a GCLID missing from the form (#04), Pixel and CAPI not deduplicated (#05) and a conversion counted twice on reload (#10). Fictional data: nothing is sent to Google or Meta.

1 · Arrive from an ad

Simulates the landing URL. Parameters are read and stored in first-party storage for 90 days.

No attribution stored yet.

2 · Fill the form

Hidden fields are filled from storage, so the CRM receives the click even if the URL lost it.

3 · Thank-you page

The dataLayer receives generate_lead with an event_id. Reloading the page must not count it again.

4 · Same lead, server side

The server sends the lead to the Meta Conversions API with the same event_id (and event name). Meta deduplicates a browser and a server event when both match, within 48 hours (official documentation, read 2026-11-18). Without it, HVAC·PHX counted leads ~1.7× (#05).
